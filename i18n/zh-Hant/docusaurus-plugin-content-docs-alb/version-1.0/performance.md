# 性能調優

## 調優總原則

1. **先測量，後調優**：基於監控數據定位瓶頸，避免盲目調參
2. **逐項調整**：每次只調整一項參數並做壓測對比
3. **關注長尾**：P99 延遲往往比平均值更能反映真實體驗

## JVM 內存調優

```bash
# JVM 堆內存調優示例（以 64 GB 內存主機爲例）
export JAVA_OPTS="-Xms32g -Xmx32g -XX:+UseG1GC -XX:MaxGCPauseMillis=200"
```

- 堆內存建議設置爲物理內存的 50% 左右
- 使用 G1 或 ZGC 收集器，控制單次停頓在 200ms 以內

## 核心調優參數

| 參數 | 默認值 | 調優建議 |
|------|--------|---------|
| server.workers | CPU 核數 | CPU 密集場景保持默認；IO 密集可上調至核數 × 2 |
| 連接池上限 | 200 | 根據壓測併發量調整，避免過大導致上下文切換 |
| 批處理大小 | 100 | 吞吐優先可增大；延遲優先可減小 |
| 刷盤策略 | async | 強一致場景改爲 sync，注意性能損耗 |

## 基準參考數據

以下爲參考硬件（16 核 / 64 GB / NVMe SSD）上的典型基準表現：

| 指標 | V2.0 參考值 | V1.0 參考值 |
|------|------------|------------|
| 單節點吞吐 | 15 萬 TPS | 9 萬 TPS |
| P99 延遲 | 8 ms | 15 ms |
| 集羣故障恢復時間 | 小於 30 s | 小於 60 s |

:::warning 注意
基準數據與業務模型強相關，實際表現請以自身業務壓測結果爲準。
:::

## 監控與持續優化

- 開啓監控指標導出，接入企業統一監控平臺（Prometheus）
- 定期評審慢日誌與 GC 日誌，建立性能基線
- 大版本升級前完成全量回歸壓測
