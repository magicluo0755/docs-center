# 产品文档中心 — 开发者使用指南

> 版本：v1.0（2026-09-25）｜适用项目：`docs-center/`（Docusaurus 3.10 多实例架构）
> 读者：向文档中心贡献内容的开发者、产品经理、技术写作人员
> 配套文档：《文档中心-设计与实现技术文档》（架构原理）、《文档中心-需求规格文档》（需求口径）

---

## 1. 五分钟理解架构

```text
products/<产品id>/docs/*.md     ← 你日常只写这里（当前版源文件，唯一信源）
        │
        ├─ npm run build ──→ 三语言静态站点（简中原文 / en 翻译 / zh-Hant 自动派生）
        └─ npm run pdf:all ─→ 54 份 PDF 制品（9 产品 × 3 语言 × 2 版本）
```

三条铁律：

1. **简体中文源是唯一事实来源**——英文手工翻译、繁体由脚本派生，都不改简中源；
2. **当前版（V2.0）可自由修改，冻结版（V1.0）只接受 bug 修复回传（backport）**；
3. **元数据分两处登记**（见 §3 场景 A）：`docusaurus.config.ts`（站点结构）与 `src/utils/products.ts`（展示层），新产品两边都要加。

## 2. 日常写作：现有产品、现有版本内更新

### 2.1 文件怎么放

| 要做什么 | 在哪里操作 |
|---------|-----------|
| 新增/修改某产品文档页 | `products/<id>/docs/<页面id>.md` |
| 调整侧边栏顺序/分组 | `products/<id>/sidebars.ts`（按文件 id 列出） |
| 新增页面并排进目录 | md 头部写 `sidebar_position: N`（数字越小越靠前；首页固定 0） |
| 插入图片 | 放 `products/<id>/docs/img/`，正文相对路径引用 `![](./img/xxx.png)` |
| 提示框 | `:::note` / `:::tip` / `:::warning` / `:::danger`（PDF 管线已适配渲染） |
| 代码高亮 | 标准 md 代码块 + 语言标注（bash/yaml/python/xml 等均已验证） |

### 2.2 frontmatter 最小约定

```markdown
---
title: 安装手册            # 页面标题（PDF 章节名/书签/页眉都取自这里）
sidebar_position: 3        # 侧边栏与目录顺序
---

# 安装手册                  # 一级标题与 title 保持一致（章节序号会自动注入）
```

> ⚠️ 正文一级标题**不要自带章节序号**（"第一章"）——PDF 管线抓取阶段自动注入中文「第一章」/英文「CHAPTER N.」序号，手写会双重编号。Web 端显示不受影响。

### 2.3 翻译流程

| 语言 | 流程 |
|------|------|
| 英文（en） | 手工翻译：在 `i18n/en/docusaurus-plugin-content-docs-<id>/{current,version-1.0}/` 维护与源文件同名的 md。**未翻译的页面会回退显示简中原文，不阻塞构建** |
| 繁体（zh-Hant） | 全自动：`npm run gen:hant`（OpenCC 从简中源幂等重建，随时可重跑） |

### 2.4 本地预览与交付验证

```bash
npm run start                              # 热更新写作预览（默认简中）
npm run build && npm run serve:static      # 生产形态预览（127.0.0.1:3000）
npm run verify                             # 提交前一键回归（路由/索引/PDF 库存/搜索 E2E）
```

## 3. 场景 A：新增产品

以新增 `abc`（金蝶Apusic XX 平台）为例，**按顺序执行 9 步**：

### Step 1 创建内容目录

```text
products/abc/
├── docs/
│   ├── index.md           # 产品首页（sidebar_position: 0，不进 PDF）
│   ├── intro.md           # 产品简介（PDF 第一章，从它开始）
│   ├── quick-start.md / installation.md / usage.md /
│   ├── configuration.md / development.md / performance.md
│   └── img/
└── sidebars.ts            # 可整体复制 products/aas/sidebars.ts 后改文件 id 列表
```

> 章节骨架（简介/快速开始/安装/使用/配置/开发/性能调优）与 PDF 管线默认目录约定一致；如产品章节不同，见 Step 6 同步修改。

### Step 2 站点结构登记 — `docusaurus.config.ts`

顶部 `products` 数组加一行（多实例插件循环自动生效，无需改 docPlugins）：

```ts
{id: 'abc', label: '金蝶Apusic XX 平台', line: 'ai'},   // line: middleware | data | ai
```

### Step 3 展示层登记 — `src/utils/products.ts`

`PRODUCTS` 数组加一条（导航栏下拉、侧边栏头、面包屑、首页卡片全部由它驱动）：

```ts
{id: 'abc', short: 'AXX', zh: '金蝶Apusic XX 平台', hant: '金蝶Apusic XX 平臺',
 en: 'Apusic XX Platform', lineZh: 'AI 平台', lineHant: 'AI 平臺', lineEn: 'AI Platform'},
```

> 命名口径：中文名「金蝶Apusic + 产品名」、英文全称「Apusic + …」、对外简称大写缩写（参考 §技术文档 4.13 命名清单）。

### Step 4 搜索索引登记

`docusaurus.config.ts` 中 search-local 插件 options 的 `docsRouteBasePath` 数组**追加 `'abc'`**（漏掉则新产品文档**静默不进索引**，构建不报错）。

### Step 5 导航栏翻译

`i18n/en/docusaurus-theme-classic/navbar.json` 与 `i18n/zh-Hant/.../navbar.json` 各补一条（键 = 中文产品名原文）：

```json
"item.label.金蝶Apusic XX 平台": { "message": "Apusic XX Platform" }
```

### Step 6 PDF 管线登记 — `scripts/pdf/generate.js`

- `PRODUCT_NAMES` 加 `abc: { zh: "...", hant: "...", en: "..." }`（封面/页眉/元数据用）；
- 若章节结构与默认七篇不同，改 `DOCS` 数组（顺序 = PDF 章节顺序，标题三语）。

### Step 7 工程化登记（4 处枚举）

| 文件 | 改什么 |
|------|--------|
| `scripts/pdf/release-all.js` | `PRODUCTS` 数组加 `"abc"` |
| `.github/workflows/ci.yml` | `pdf-release` 矩阵 `product:` 列表加 `abc` |
| `scripts/regression.sh` | 两处 `for p in aas admq ...` 循环加 `abc` |
| `crowdin.yml` / `CODEOWNERS` | 加对应文件枚举块 / 产品目录分权（可选） |

### Step 8 翻译派生

```bash
npm run gen:hant     # 自动为新产品派生繁体（zh-Hant 目录）
# en 翻译目录 i18n/en/docusaurus-plugin-content-docs-abc/ 可后补，缺失回退简中
```

### Step 9 全链路验证

```bash
npm run build
npm run serve:static        # 浏览器核对 /abc/ 三语言、侧边栏头、面包屑、搜索
npm run verify              # 回归全绿
npm run pdf:all             # PDF 出 6 份新增（3 语言 × 2 版本）
```

## 4. 场景 B：现有产品发布新版本

以 AAS 发布 **V3.0**（当前 V2.0 冻结）为例：

### Step 1 冻结当前版（CLI 自动完成）

```bash
npx docusaurus docs:version:aas 2.0
```

自动生成：`aas_versioned_docs/version-2.0/`（快照）+ `aas_versioned_sidebars/version-2.0-sidebars.json` + `aas_versions.json` 追加 `"2.0"`。

> ⚠️ 多实例的版本快照**必须**落在站点根目录并带插件 id 前缀（CLI 已按此行为）；手工操作时勿放进 `products/<id>/` 下。

### Step 2 版本语义登记 — `docusaurus.config.ts`

该产品实例的 `versions` 改为三段式：

```ts
versions: {
  current: {label: 'V3.0', path: '', banner: 'none'},      // 新版占根路径
  '2.0':   {label: 'V2.0', path: '2.0', banner: 'none'},   // 冻结版
  '1.0':   {label: 'V1.0', path: '1.0', banner: 'none'},
},
```

> `banner: 'none'` 必须显式：否则 Docusaurus 把 versions.json 最后项当"最新发布版"，当前版页面顶部出现反向横幅。

### Step 3 内容演进规则

| 版本 | 位置 | 规则 |
|------|------|------|
| V3.0（当前版） | `products/aas/docs/` | 自由修改，新功能文档写这里 |
| V2.0（冻结） | `aas_versioned_docs/version-2.0/` | **只接受 bug 修复 backport**，直接改快照文件 |
| V1.0（冻结） | 同上 | 同上 |

### Step 4 翻译同步

- en：复制 `i18n/en/docusaurus-plugin-content-docs-aas/current/` → `version-2.0/`（冻结版翻译随版本走）；
- zh-Hant：`npm run gen:hant` 会为 versioned 目录一并重建。

### Step 5 PDF 管线版本登记

| 文件 | 改什么 |
|------|--------|
| `scripts/pdf/generate.js` | `verLabel()` 增加映射：`current → "V3.0"`、`"2.0" → "V2.0"` |
| `scripts/pdf/release-all.js` | `VERSIONS` 数组加 `"2.0"` |
| `.github/workflows/ci.yml` | `pdf-release` 矩阵 `version:` 加 `"2.0"` |
| `scripts/regression.sh` | PDF 库存循环 `for v in ...` 加 `V2.0`（并同步 54 → 72 份总数期望） |

### Step 6 版本保留策略

`<id>_versions.json` **仅保留最近 2 个版本**；退出维护的旧版本归档至 Git tag（`docs-aas-v1.0`），必要时按 tag 检出重建。

### Step 7 验证

同场景 A Step 9；重点核对：新版占根路径 `/aas/`、冻结版 `/aas/2.0/` 可访问、版本下拉三项齐全、PDF 三版本 × 三语言 = 9 份/产品。

## 5. 高频坑速查

| 症状 | 原因与处置 |
|------|-----------|
| 新产品页面搜索不到 | search-local `docsRouteBasePath` 漏加产品 id（静默失败，§技术文档 10.1） |
| 构建成功但页面报 Module not found | 删除过 swizzle 组件后未 `npx docusaurus clear`，webpack 缓存残留 |
| 当前版页面出现「此为尚未发行版本」横幅 | 版本配置漏 `banner: 'none'` |
| 英文站部分页面仍是中文 | en 翻译目录缺同名文件（回退机制，属预期；补翻译即可） |
| 繁体搜索验证用「集群」搜不到 | OpenCC 把集群转作「集羣」，验证关键词须用转换后写法 |
| 回归/抓取偶发 404 | `localhost` 在双栈环境可能解析 ::1 撞上其他进程，一律用 `127.0.0.1` |
| 预览用 docusaurus serve 部分页面 404 | 该命令对版本化 index 路由有缺陷，改用 `npm run serve:static` |
| PDF 章节出现双重「第一章」 | 正文一级标题手写了序号；序号由管线自动注入，源文件不要写 |
