## 1. 概述

基于 **Docusaurus 3.10**（静态站点生成）+ **Paged.js/Puppeteer**（PDF 出稿）构建的企业级多产品文档中心原型。当前状态：

### 1.1 开发原则：先复用原生，再最小扩展

本项目定制面已经不小（3 处 swizzle + 自建 PDF 管线 + 文档生成脚本），**任何新需求先判定落在哪一层，逐级往上才允许动**：

| 档 | 手段 | 说明 |
|---|---|---|
| 1 | `docusaurus.config.ts` 原生字段 / 插件配置 | 首选。多数需求框架已有开关（`editUrl`、`sidebar.items`、`themeConfig.*`） |
| 2 | 现有 slot 挂独立组件 | 找语义相近的原生组件，wrap 后在其旁边插自己的组件 |
| 3 | 单点 swizzle | 能用 wrap 就不 eject，只覆盖单个组件 |
| 4 | 覆盖渲染链路 / 复制整份主题 / 侵入 build 产物 | 默认禁止，除非 1–3 全都无法表达需求 |

**红线**

- 不覆盖框架默认渲染（`h1`、`DocItem/Layout`、`Root` 等），否则会连带丢默认行为，每次升级都要重新核对；
- 不为单个 UI 需求自建数据管线（多一张映射表就多一处会漂移的真相）；
- 交付时必须能一句话说清「动了哪些默认行为」，说不清就是改多了。

**流程**：先给「原生 / 最小扩展 / 激进」三档方案对比（代价、风险、会动的默认行为、能否回退）再让用户决策；评估代价明显过大或与内核升级冲突时**主动提醒、建议不做**。

> 反例见 §5.5 演进记录：为让按钮与标题同行而覆盖 MDX `h1`，代价是字号规则失效 + PDF 抓取需额外排除 + 清缓存，最终整版回退。

## 2. 总体架构

```text
Markdown（唯一信源，252 篇）
  ├─→ Docusaurus SSG ─→ 静态 HTML 站点（多产品/多版本/多语言路由）
  │                      ├─ nginx / Docker 容器托管
  │                      └─ PDF 管线消费：抓取正文 → 封面+目录 → Paged.js 分页 → PDF
  └─→ 版本冻结：发版时快照至 <id>_versioned_docs/version-x.x/（只接受 backport）
```

- **选型结论**：Docusaurus 是唯一同时原生满足「多产品（multi-instance）+ 多版本（version snapshot）+ 多语言（i18n）」的 SSG 框架（对比 VitePress / MkDocs 详见《企业级文档中心解决方案.md》）
- **PDF 管线选型**：Paged.js + 无头浏览器（MIT 开源），替代方案 Prince XML（商用收费）

**关键约定（踩坑得出）**：Docusaurus 3.x 多实例的版本文件必须放**站点根目录**并加插件 ID 前缀（`aas_versioned_docs/`），不能放 `products/<id>/` 下——源码 `plugin-content-docs/lib/versions/files.js` 按此逻辑定位。

**真实内容的多语言约定（2026-09-29 与需求方确认）**：

1. **三语言 md 均为独立成稿的翻译件**（人工翻译/翻译公司交付），分别放置于：
   - 简体（源语言）：`products/<id>/docs/` 与 `<id>_versioned_docs/version-X.Y/`
   - 英文：`i18n/en/docusaurus-plugin-content-docs-<id>/{current,version-X.Y}/`
   - 繁体：`i18n/zh-Hant/docusaurus-plugin-content-docs-<id>/{current,version-X.Y}/`
   - 目录结构与简体严格镜像（同名文件、同相对路径），Docusaurus i18n 按路径一一对应加载。
   - `generate_hant.py`（OpenCC s2t）定位为 **demo 阶段加速器**：真实内容阶段可选用于繁体初翻/术语一致性辅助，产出仍作为独立文件人工校订，不再作为"派生物"整体重灌。
2. **界面截图按语言分版本**（产品本身支持 i18n，Web 界面截图随 UI 语言变化）：
   - 手册类文档中的截图**禁止放 `static/`**（static 为全站共享，无法本地化），一律放文档目录内部、md 中用**相对路径**引用（如 `![登录页](./img/login.png)`）；
   - 各语言目录镜像各自携带自己的图片子目录：`products/aas/docs/installation/img/*.png`（简中截图）、`i18n/en/.../installation/img/*.png`（英文截图）、`i18n/zh-Hant/.../installation/img/*.png`（繁体截图）——同路径同名，构建时各自解析；
   - 命名建议 `<功能名>-<状态>.png` 三语言保持一致，仅图片内容不同，便于 diff 与批量替换；
   - 版本快照目录同理：版本冻结时图片随 md 一并复制进 `<id>_versioned_docs/version-X.Y/` 对应 img 子目录。
3. **翻译交付物验收口径**：按"目录树镜像完整性"验收——简体侧每个 md 及其引用的每张图，在 en/zh-Hant 侧均有同路径对应物；可用脚本比对文件清单（待办：迁移时补一个 i18n 镜像完整性检查加入 regression）。

**部分产品/版本缺失翻译的处理（2026-09-29 实现）**：

真实接入中个别产品/版本可能仅有简体中文。分层策略：

1. **站点渲染层（零改动）**：Docusaurus i18n 为覆盖式叠加——`i18n/<locale>/` 下缺失的 md 自动回退渲染简体源内容，页面正常显示（已实测：移除 en 翻译后构建通过、路由 200、内容为简体回退）。
2. **PDF 出稿层（自动跳过）**：新增共享模块 `scripts/pdf/lang-coverage.js`——判定 `i18n/<locale>/docusaurus-plugin-content-docs-<id>/{current,version-X.Y}/` 下是否存在 md（zh-Hans 为源语言恒可用）；`generate.js` 遇缺失语言打印 `[SKIP]` 并以退出码 0 跳过；`release-all.js` 按同一判定整组跳过并在汇总中列出 SKIP 清单。部分翻译（目录有部分 md）视为可用，缺页由站点回退兜底。
3. **回归门禁联动**：regression.sh 的 PDF 期望值由 `expectedPdfCount()` 动态计算（全量 + 分册均按可用语言数展开），与出稿口径同源，缺失语言不触发误报；翻译交付后重跑 `npm run pdf:all` 自动补稿。

**⚠️ 已修复的历史缺陷（2026-09-29）**：`generate_hant.py` 原实现先整体 `rmtree i18n/zh-Hant` 再重建，带产品参数运行（如 `generate_hant.py aas`）会清空其余 8 个产品的繁体文档，且站点/PDF 靠回退机制静默存活、难以察觉。已改为逐产品清理重建；曾因此丢失的繁体文档已通过全量重派生恢复（154 篇）。教训：**回退机制会掩盖翻译资产丢失，新增 i18n 完整性检查后此类问题可被回归捕获**。

## 4. 核心配置（docusaurus.config.ts）

- **多实例**：`docPlugins` 数组循环 9 个产品 id，每产品一个 `@docusaurus/plugin-content-docs` 实例：`id: pid`、`path: products/<pid>/docs`、`routeBasePath: pid`、`sidebarPath: products/<pid>/sidebars.ts`、`versions: { current: {label:'V2.0', path:'', banner:'none'}, '1.0': {label:'V1.0', path:'1.0'} }`
  - `banner: 'none'` 必须显式设置：否则 Docusaurus 把 versions.json 里的最后版本当"最新发布版"，当前版页面出现"此为尚未发行版本"反向横幅
  - 版本路径显式指定：默认最新发布版占根路径，需设 `current.path: ''`（V2.0 根路径）+ `'1.0'.path: '1.0'`
- **i18n**：`locales: ['zh-Hans', 'zh-Hant', 'en']`、`defaultLocale: 'zh-Hans'`、`localeConfigs` 标签
- **themes**：`@easyops-cn/docusaurus-search-local@0.55.3`（配置见 §10）
- **导航栏**：`{type: 'localeDropdown', position: 'right'}`（产品名与版本切换已移至左侧导航栏顶部，见 §5.2；语言下拉保留在导航栏右侧）

### 5.1 产品元数据注册表 — `src/utils/products.ts`

单一事实源：产品 id → 中文名/繁体名/英文名/产品线（三语）。导出 `resolveProductContext(pathname)`：剥离 locale 前缀（en / zh-Hans / zh-Hant）→ 匹配产品 → 从路径段解析版本（`/1.0/` → V1.0，否则 V2.0）；另导出 `productName()/productLine()/localePrefix()/localeFromPath()` 供组件按 locale 取名。

> ⚠️ 踩坑：切片后残留前导斜杠，版本判断必须用 `startsWith('/1.0/')` 而非 `'1.0/'`，否则英文 V1.0 页误判为 V2.0（已修复）。
> 新增产品：在 `PRODUCTS` 数组加一条即可，侧边栏头部与面包屑自动生效。

### 5.2 侧边栏「产品名 + 版本下拉」头部（Red Hat 文档形态）

参考 Red Hat 文档交互：产品名与版本切换器位于**左侧导航菜单栏顶部**（2026-09-25 由顶部导航栏迁入，原导航栏自定义下拉与正文「当前阅读」上下文条已废弃删除）。实现为三个 swizzle 协作：

- **`src/components/SidebarProductHeader.tsx`**（共享组件）：`resolveProductContext` 判定当前产品 → 渲染产品名 + `DocsVersionDropdownNavbarItem`（`mobile` 属性区分桌面 hover 下拉 / 移动端点击下拉）

### 5.5 文档页动作行：编辑此页 / 下载 PDF

设计取向：**能用原生就用原生**——不接管标题渲染、不自建路径映射。

| 动作 | 实现 | 位置 |
|---|---|---|
| 编辑此页 | docs 插件 `editUrl`（函数形式）+ 主题自带 `theme/EditThisPage` | 文档页脚，正文末尾 |
| 下载 PDF | swizzle `theme/EditThisPage`，在原生链接旁并排 `src/components/DownloadPdfLink/` | 同上，同一行 |

两个动作都在页脚，属于「页面级元操作」，与站点自带的编辑入口天然成组；打印与 PDF 出稿自动排除（`.theme-doc-footer` 在抓取阶段被剔除，`EditMetaRow` 自身也有 `noPrint`）。

> 演进记录：曾做过两版更"显眼"的方案——① 自定义 navbar item（顶部导航栏右侧）；② swizzle `DocItem/Content` 覆盖 MDX `h1`，把按钮挂到标题行右侧。两者都能用，但都改了默认的标题渲染链路（后者还要补回 `--ifm-h1-font-size`、并把按钮从 PDF 抓取里剔除），维护成本高于收益，现已全部回退，只留页脚这一版。

**① 编辑此页 —— 原生 editUrl**

`docusaurus.config.ts` 里每个 docs 实例都配同一个函数（不能用字符串：本项目是多实例 + 冻结版 + i18n 三套目录）：

```ts
editUrl: ({versionDocsDirPath, docPath, locale}) => // 见实现
```

- `versionDocsDirPath` 由插件给出，是**文档源目录**：`products/<p>/docs` 或 `<p>_versioned_docs/version-1.0`
- `docPath` 是该目录内的相对路径
- 非默认语言时先试 `i18n/<locale>/docusaurus-plugin-content-docs-<p>/<current|version-1.0>/<docPath>`，`fs.existsSync` 命中即用；**缺翻译自动回落到简体源文件**（页面上回退显示的正是它，改它才对）

i18n 文案用的是主题内置翻译（`theme.common.editThisPage`）：编辑此页 / 編輯此頁 / Edit this page，无需自建 `code.json`。

**② 下载 PDF —— 只给当前页所属手册**

判定链：路由 → 产品 / 版本 / 语言 / 页面 slug（`resolveDocRoute`）→ 查 PDF 清单 → 匹配手册收录范围。

```
/aas/installation/standalone
  → 唯一命中「安装手册」（matchers: intro + dir installation）
  → aas-V2.0-zh-Hans-installation-guide.pdf

/aas/intro
  → 3 本手册都收录了 intro（歧义）→ 回退全量合集 aas-V2.0-zh-Hans.pdf

/adc/intro
  → 该产品无分册 → 全量合集 adc-V2.0-zh-Hans.pdf
```

规则：**唯一命中分册 → 下分册；命中多本或未命中 → 回退全量；全量也没有但只有一本分册 → 下该分册；都没有 → 整项不渲染**（缺失翻译的产品/语言自动降级，与 PDF 出稿的跳过逻辑同源）。

数据来自构建期生成的 `src/data/pdf-manifest.json`（`scripts/pdf/build-manifest.js`）：扫描 `output/pdf` 得到**实际存在**的 PDF（含字节数用于 tooltip 显示体积），再用 `manuals.json` 的 `docs` 条目转成 matcher（字符串 → `exact`，`{dir}` → `dir` 前缀）。

PDF 由 `scripts/pdf/sync-assets.js` 同步进 `static/downloads/pdf/`，访问路径 `/downloads/pdf/<product>/<version>/<locale>/<file>.pdf`，构建产物自包含（nginx 不再 alias 到站点外目录）。

> ⚠️ 踩坑：**不要用 `useBaseUrl` 拼 PDF 路径**。Docusaurus 在非默认语言构建时会把 locale 拼进 `siteConfig.baseUrl`（en 下为 `/en/`），而 PDF 路径里**已经带了语言目录**，直接拼会得到 `/en/downloads/pdf/...` 的死链。正确做法是剥掉 baseUrl 里的 locale 段；回归里有专门一条「PDF 链接无 locale 前缀污染」守着。

**构建接入**：`npm run prepare:assets` 串联两个生成器（PDF 清单 → PDF 同步），挂在 `prestart` / `prebuild` / `prebuild:en` 上。产物 `src/data/pdf-manifest.json` 与 `static/downloads/` 均已 gitignore。

**回归覆盖**（`regression.sh` §3c + `scripts/verify_doc_actions.js`）：PDF 静态目录产出数量、locale 前缀污染、5 条代表性路由（简中/英文/繁体/冻结版/无分册产品）的 PDF 与编辑链接目标比对、首页不出现动作入口；全站 456 页再断言两链接各一个、都在 `<footer>` 内、且编辑链接指向的文件真实存在。

## 6. PDF 出稿管线 — `scripts/pdf/`

**generate.js（核心，~300 行）**，四步：

1. **抓取**：从运行中的站点（`http://localhost:3000`）按 sidebar 章节顺序抓取各页面，cheerio 提取 `article` 正文，剔除分页导航/面包屑/版本徽标/浮动目录等 Web 元素；标题从 frontmatter meta 提取（截断 `| 站点名` 后缀）
2. **组装 HTML**：封面（Red Hat 式白底版式：横版 logo + 产品名 + 版本 + 文档名 + 副标题 + 右下发布日期；产品名/版本/文档名三行统一 26pt 常规字重，密级经 `showClassification:false` 隐藏）+ 法律声明页（`notice.<lang>.html` 模板占位符渲染）+ 目录页 + 各章节（`chapter` 类，每章起新页）
3. **分页渲染**：Paged.js polyfill + puppeteer-core 驱动**本机 Edge**（`puppeteer-core` + msedge.exe 路径探测，免下载 Chromium）
4. **输出**：`output/pdf/{product}/{version}/{lang}/` 归档；`page.pdf({ outline: true })` 按标题层级（h1→h2→h3）自动生成 PDF 书签

**关键技术点**：
- PDF 书签（outline）：puppeteer ≥ 21 的 `outline: true`（CDP `generateDocumentOutline`），Chrome 从 DOM 标题层级自动构建书签树——因此封面标题必须用 `div` 而非 `h1`（避免封面混入书签）；声明页 h1/h2 与章节 h1/h2 自然形成「法律声明 → 版权声明…」「章节 → 小节」两级/三级书签，经 pypdf 验证 45 条书签页码定位准确
- **章节序号（需求 4.10；2026-09-29 修订）**：抓取聚合阶段对 h1/h2/h3 注入序号——中文 h1 `第1章 标题`（**阿拉伯数字**，序号与标题间一个空格）、英文 h1 `CHAPTER 1. Title`（数字后带句点，句点后一个空格）；子标题中英一致 `1.1. 标题`/`1.1.2. 标题`（层级小数序号 + 句点结尾 + 一个空格再接标题）。序号同时进入目录条目、书签、页眉。仅作用于 PDF，Web 端不变。**同日修订：h1 样式去除 `border-bottom` 下划线（品牌色保留），避免与页眉横线视觉重复**
- **admonition 渲染**：Docusaurus 的 admonition 图标 SVG 仅带 viewBox 无宽高、脱离站点 CSS 后会被撑满整页——须显式约束 `.theme-admonition svg {width:1.15em;height:1.15em}`；注意实际类名是 `theme-admonition`（非 `admonition`）、标题为带哈希后缀的 `admonitionHeading_xxx`，选择器需用前缀匹配
- **文件锁健壮性**：先写 `.tmp-<pid>.pdf` 再原子替换，EBUSY/EPERM 重试 5 次后依次尝试 `-updated.pdf`、`-updated-<ts>.pdf` 时间戳兜底名，绝不静默丢稿；临时 HTML 清理失败仅告警不影响交付
- 封面/声明页定制三层覆盖：CLI（`--doc-title/--logo/--date`）> `scripts/pdf/cover.config.json`（公司名双语、logo 路径、副标题、密级、dateLabel）> 内置默认；声明页为独立模板 `notice.zh-Hans.html` / `notice.en.html`（占位符 `{{COMPANY}}/{{PRODUCT}}/{{VERSION}}/{{MANUAL}}/{{DATE}}/{{YEAR}}/{{CLASSIFICATION}}`），法务口径变更只改模板不动代码
- PDF 元数据标题取自 `<title>`（产品名 + 版本 + 文档名），阅读器标题栏/搜索索引友好
- 目录页码：CSS `target-counter(attr(href url), page)` 由 Paged.js 分页后自动回填真实页码
- 虚线引导线（传统 docx 目录样式）：TOC 项为 flex 布局 `<span class="toc-title"> + <span class="toc-dots">`，空占位元素的基线为其底边框，虚线恰好落在文字基线上——与 `target-counter` 完全兼容
- 页眉页脚：`string-set` 页眉显示当前章节名（左对齐），页脚页码（左下），封面页隐藏。**分隔横线的坑**：Paged.js 对 top margin box 的 `border-bottom` 渲染不稳定（正文页丢线、toc 页反而有线），改用 `@page` 的 `background-image` 双 `linear-gradient` 定位画线（`background-position: 18mm 21.3mm / 18mm 277.6mm`，`size: 174mm 0.35mm`，`@page cover` 置 `none`）——与 margin box 解耦，逐页稳定
- pagedjs 的 `dist/paged.polyfill.js` 被 package exports 屏蔽，需按物理路径引用
- 品牌资产：官方 logo 经 PIL 裁透明边后入库——`static/img/apusic-logo-mark.png`（无文字标 535×205，导航栏用）、`static/img/apusic-logo-horizontal.png`（横式图文组合 594×129，PDF 封面用 84mm 宽）；源文件带大面积透明画布，**必须 `alpha.getbbox()` 裁边**否则版面留白失衡
- 书签验证工具：pypdf（venv `~/.workbuddy/binaries/python/envs/`）读 outline 树 + 目标页码；封面/声明页视觉验证用 `snapshot.js` 截图

**配套脚本**：
- `release-all.js`：发版全量出稿（CI `pdf:release` 任务的本地等价物），9 产品 × 3 语言 × 2 版本全量合集 + manuals.json 分册（当前 AAS 3 册 → 合计 **72 份**），实测 6 分 46 秒（54 份时期）
- `snapshot.js`：Paged.js 渲染结果逐页截图（`--pages N`），用于 CI 视觉回归
- `verify_all.py`：全量 PDF 书签数量完整性检查（全量合集 ≥20、分册 ≥5 阈值）+ 目录文本抽查（pymupdf）；路径基于脚本位置解析，换盘/迁移后依然有效
- `debug_search.js`：搜索 UI 调试工具（控制台/网络错误捕获 + 截图）

**npm scripts**：`npm run pdf -- --product aas --version current --lang zh-Hans`（单份全量）；`npm run pdf -- --product aas --version current --lang zh-Hans --manual installation-guide`（分册）；`npm run pdf:all`（全量+分册遍历）。前置条件：`build` + `serve`。

**分册 PDF 机制（2026-09-28 新增，需求：按手册自由组合出 PDF）**：
- **配置源 `scripts/pdf/manuals.json`**：手册 = `{ id, title(三语), docs(有序条目) }`；产品级 `manuals` 对所有版本生效，`versions["1.0"].manuals` 可整体覆盖该版本组合
- **条目形态**：`"slug"`（单页，含嵌套路径；若文档源存在同名目录则自动按目录展开）或 `{ "dir": "路径" }`（显式目录展开）；展开规则对齐 Docusaurus autogenerated sidebar——`index.md` 为 landing 排首，其余按 frontmatter `sidebar_position` 排序（**2026-09-29 修订：移除「编（Part）」层级，子目录仅作排序容器，不再产生分组，md 文档为扁平结构**）
- **章节层级**：仅「章（每页）→ 节（h2/h3）」两级，章号全书连续（2026-09-29 移除编（Part）分组行、编分隔页及 `@page part` 相关 CSS 与 `partLabel()`/`zhPartNum()` 代码）
- **CLI**：`--manual <id>` 选册，不传 = 全量合集（向后兼容，其 DEFAULT_DOCS 同样支持目录展开，AAS 全量已自动扩为 11 章）；未知 id 报错并列出该产品可用手册
- **输出命名**：分册 `aas-V2.0-zh-Hans-installation-guide.pdf`，与全量 `aas-V2.0-zh-Hans.pdf` 同目录并存；封面文档名/声明页 `{{MANUAL}}` 取清单 `title[lang]`
- **管线复用**：章节序号、目录页码回填、页眉页脚、书签、封面/声明页全部零改动
- **回归联动**：regression.sh PDF 库存期望值由 manuals.json 动态计算（node 内联：54 + Σ分册×3语言×2版本）；verify_all.py 按文件名后缀识别分册并放宽书签阈值
- **文件锁坑**：`present_files`/阅读器预览占用 PDF 时原子替换失败走 `-updated.pdf` 兜底——重出前先关闭预览，或事后用 `mv` 手工替换

### 10.1 全文检索索引未生成 —— ✅ 已解决（2026-09-25）

- **现象**：`docusaurus-search-local@0.55.3` 构建成功、搜索页 200，但全 build 目录无索引 JSON；DEBUG 日志 postBuild 走到 "parsing documents" 后无下文且不报错
- **根因**：插件的 `docsRouteBasePath` **默认 `["docs"]`**、`indexPages` **默认 false**。多实例的 routeBasePath 是 `aas/admq/...`，与默认值不匹配 → `processDocInfos` 里所有路由既不命中 docs 分支也不命中 page 分支 → 全部过滤 → 返回空数组 → postBuild 循环体零次执行、正常返回（ hence 构建无任何报错）
- **修复**：在插件 options 显式声明 `docsRouteBasePath: ['aas','admq','adc','alb','amdm','adgp','aig','akm','amem']`（新增产品需同步追加此数组）
- **产物**：每语言 10 个索引（根 + 9 产品目录），共 20 个；根索引聚合所有「最新发布版（V1.0）」文档供首页/搜索页使用，产品索引（如 `build/aas/search-index.json`，82 条）供产品文档页使用
- **验证**：索引内容抽查（zh root 738 docs / 579KB，en 526KB，含中文分词内容）；端到端搜索通过 `scripts/verify_search.js`（无头浏览器输入关键词断言结果渲染）：中文「集群」、英文 "gateway"、首页根索引三场景全部命中，结果带高亮 + 面包屑路径 + 上下文摘要
- **面包屑本地化（已解决）**：索引 breadcrumb 首项取自页面 `.navbar__link--active` 文本（插件 parseDocument.js），导航栏「首页」项未配翻译导致英文索引出现 `b:["首页"]`——在 `i18n/en/docusaurus-theme-classic/navbar.json` 补 `item.label.首页: Home` 后重建即修复

### 10.6 无头 Edge 无法启动 → 搜索 E2E / PDF 出稿受阻（2026-10-29 发现，2026-10-30 已绕过）

- **现象**：`npm run verify` 的三语言搜索 E2E 全部 FAIL，报 `Failed to launch the browser process: Code: 0`（stderr 为空）。站点本身正常（54 条路由 200、10/10 索引齐全）。
- **定位**：失败发生在**浏览器启动阶段**，与页面内容无关。`puppeteer.launch` 的 `headless: true` 与 `headless: 'new'` 均失败；直接执行 `msedge.exe --headless=new --dump-dom about:blank` 也是立即退出（rc=0、无任何输出）。
- **环境**：Edge `156.0.4314.50`（2026-10-26 更新）、puppeteer-core `25.12.0`、Node v22.22.2。上次搜索 E2E 通过是 2026-09-29，其后 Edge 升级过，疑为版本/Sandbox 策略导致子进程被拦。
- **影响**：`verify_search.js`、`verify_sidebar.js`、`screenshot_page.js`、`generate.js`（PDF 出稿）全部依赖无头浏览器，一并不可用。
- **已绕过（2026-10-30）**：本机装有 Chrome 133+，可正常无头启动。`verify_search.js` 的浏览器探测改为 **`BROWSER_PATH` 优先 → Chrome → Edge → Linux chromium**，与 `generate.js` 的约定统一；此后 `npm run verify` 三语言搜索 E2E 全部 PASS。若某台机器 Edge 仍可用、但希望强制走 Edge，设 `BROWSER_PATH` 指向 msedge.exe 即可。
- **注意**：这不是「页脚动作行」引入的问题——§3c 检查一直全部 PASS，当时只有依赖浏览器的 E2E 挂了。
- **仍缺失**：`verify_sidebar.js` / `screenshot_page.js` 尚未同步这条探测链，需要时按同样方式补。

### 10.7 开发态切换语言 404 —— 框架单语言编译（2026-10-30 定位，非缺陷）

- **现象**：`npm run start`（http://localhost:3000）下，在简体中文页点导航栏语言下拉切到 English，地址跳到 `/en/aas/intro` 但页面显示「找不到页面」（HTTP 200 + 主题 404 页）。
- **定位**：`docusaurus start` **一次只编译一种语言**（默认 `zh-Hans`），非默认语言的路由根本不存在，客户端路由匹配不到就落到 404 页。源码层面 `@docusaurus/core/lib/server/site.js` 用 `currentLocale: locale ?? i18n.defaultLocale` 建站点，dev 服务器不生成 `--locale` 以外的语言路由；CLI 的 `-l, --locale <locale>` 就是为单语言开发准备的。
- **验证**：同一台机器上生产产物（`build/` + `npm run serve:static`）三语言全部正常——`/en/aas/intro`、`/zh-Hant/aas/1.0/intro`、`/en/aig/1.0/intro` 均为 200 且 `<html lang>`、`h1` 正确；全站 465 个页面里 10426 条跨语言链接落点全部存在，每语言各 154 页。
- **结论**：**语言切换只能在生产产物上验收**，dev 态 404 属框架既定行为，不需要也不能通过改配置修好（不存在"多语言热切换"的 dev 开关）。
- **正确姿势**：

  | 场景 | 命令 |
  | --- | --- |
  | 验证三语言切换（推荐） | `npm run build` → `npm run serve:static 3200` |
  | 开发简体 | `npm run start` |
  | 开发英文 / 繁体 | `npm run start:en` / `npm run start:hant`（等价 `npm run start -- --locale en`） |

- **守门**：新增 `scripts/verify_locale_links.js`（扫描 build 内所有 `/en/`、`/zh-Hant/` 链接是否命中真实产物 + 三语言页面计数），已接入 `regression.sh` §3e，防止将来漏构建某个语言。
- **教训**：演示/验收一律指向生产预览端口；dev 端口只用于改代码看热更新。
