# 企业级产品文档中心解决方案

> 适用范围：4 个产品线 / 20+ 活跃在研产品与项目 / 多版本（每产品 ≥3 个活跃版本）/ 三语言（简体中文 zh-Hans、繁体中文 zh-Hant、英文 en）
> 方案基线：静态站点生成（SSG）+ Markdown 单一信源 + 自动化 PDF 离线分发 + Git 版本化协作

---

## 1. 需求映射总览

| # | 需求 | 方案落点 |
|---|------|---------|
| 1 | 静态站点生成、Markdown 优先 | Docusaurus 3.x（MD/MDX），Markdown 为唯一内容信源 |
| 2 | 文档直接渲染显示页面 | Docusaurus 增量构建 + CDN 部署，实时预览 |
| 3 | 多产品、多版本、多语言 | Docusaurus 多实例（multi-instance）+ 原生 Versioning + 原生 i18n |
| 4 | 自动化持续构建标准 PDF | CI 流水线独立 PDF Job：HTML → Paged.js → PDF，产物入制品库 |
| 5 | 文档版本化管理 | Git 分支/MR 管理源稿 + Docusaurus snapshot 管理发布版 |
| 6 | 多团队多人协作 | GitLab/GitHub + CODEOWNERS 按产品目录划权 + MR 评审流 |
| 7 | 多文档组织结构、PDF 跨文件聚合 | sidebar 配置文档组织结构，PDF 按 sidebar 顺序聚合多个 md |
| 8 | 代码高亮 + 注意/提醒/警告 | Shiki/Prism 高亮 + Docusaurus Admonitions（note/tip/warning/danger/info） |
| 9 | PDF 自动目录带页码 | Paged.js 目标计数（target-counter）自动生成带页码 TOC |
| 10 | 封面样式自定义 + 内置默认封面 | 封面模板库（HTML/CSS），按产品/版本参数化渲染 |

## 2. 技术选型

### 2.1 SSG 框架对比

| 维度 | **Docusaurus（推荐）** | VitePress | MkDocs Material | Hugo |
|------|----------------------|-----------|-----------------|------|
| 多产品（multi-instance） | ✅ 原生支持，每产品独立 docs 实例、独立侧边栏 | ❌ 需多站点拼装 | ❌ 需多仓拼装 | 需手工组织 |
| 文档版本化 | ✅ 原生 `docs.versioning`，一条命令冻结版本快照 | ❌ 需自建 | ❌ 需 mike+多分支（仅 mkdocs 生态） | ❌ 自建 |
| 多语言 i18n | ✅ 原生 locale 路由 + 翻译覆盖率校验 | 基础支持 | 基础支持 | 强但需自建工作流 |
| MDX 扩展 | ✅（可嵌交互组件） | ✅ | 有限 | 有限 |
| Admonitions / 代码高亮 | ✅ 内置 | ✅ | ✅ | ✅ |
| 构建性能（20+ 产品） | 增量构建 + 多实例并行，可接受 | 快 | 中 | 最快 |
| PDF 生态适配 | 成熟（基于 HTML 路由爬取） | 可行 | 可行 | 可行 |

**结论**：多产品 + 多版本 + 多语言三个硬性需求同时原生满足的只有 Docusaurus，选定为 SSG 基座。

### 2.2 PDF 生成方案对比

| 维度 | **Paged.js + Puppeteer（推荐）** | Prince XML | Pandoc + LaTeX |
|------|-------------------------------|------------|----------------|
| 许可 | MIT 开源，免费商用 | 商业许可（按部署收费） | 开源 |
| 自动 TOC 带页码 | ✅ CSS `target-counter` | ✅ 原生 | ✅ 但模板定制难 |
| 封面自定义 | ✅ HTML/CSS 模板，最灵活 | ✅ | 弱 |
| 中文排版 | ✅ Chromium 渲染，中文字体成熟 | ✅ | 中文字体配置繁琐 |
| 与 Docusaurus 集成 | ✅ 直接消费其构建产物 HTML | ✅ | 需回退到 md 源，丢失 admonition 样式 |
| 页眉页脚/页码 | ✅ @page 规则 | ✅ | ✅ |

**结论**：PDF 管线选定 **Paged.js + Puppeteer（无头 Chromium）**，直接以 Docusaurus 构建出的站点 HTML 为输入，按 sidebar 结构爬取聚合，保证 Web 端与 PDF 端视觉一致。备选 Prince XML（若未来对排版精度要求极高再引入）。

## 3. 总体架构

```
┌────────────────────────── 文档源仓库（Git Monorepo）──────────────────────────┐
│  docs-repo/                                                                  │
│  ├── products/                                                               │
│  │   ├── product-a/                                                          │
│  │   │   ├── docusaurus.config.ts        # 产品实例配置                       │
│  │   │   ├── sidebars.ts                 # 文档组织结构（章节树）              │
│  │   │   ├── docs/                       # 当前开发版（next/最新版）           │
│  │   │   │   ├── intro.md  guide/  reference/  ...                           │
│  │   │   ├── versioned_docs/             # 已发布版本冻结快照                 │
│  │   │   │   ├── version-2.3/  version-2.2/                                  │
│  │   │   ├── i18n/                       # 三语言翻译内容                     │
│  │   │   │   ├── zh-Hans/  zh-Hant/  en/                                     │
│  │   │   └── pdf/                        # PDF 封面模板 + 输出配置            │
│  │   ├── product-b/ ...                                                      │
│  ├── shared/                             # 共享组件、 admonition 样式、封面库   │
│  ├── scripts/pdf/                        # Paged.js PDF 生成脚本              │
│  └── .gitlab-ci.yml / .github/workflows  # CI/CD 流水线                      │
└──────────────────────────────────────────────────────────────────────────────┘
                 │                                        │
        ┌────────▼────────┐                     ┌─────────▼─────────┐
        │  Web 站点构建 Job │                     │   PDF 构建 Job     │
        │  (增量构建/并行)  │                     │ (按产品×版本×语言)  │
        └────────┬────────┘                     └─────────┬─────────┘
                 │                                        │
        ┌────────▼────────┐                     ┌─────────▼─────────┐
        │ CDN / 对象存储    │                     │ PDF 制品库         │
        │ 文档中心门户站点   │                     │ → 分发 / 交付下载   │
        └─────────────────┘                     └───────────────────┘
```

核心设计原则：

1. **Monorepo 单仓多实例**：20+ 产品在同一仓库内，每个产品一个 Docusaurus docs 实例（`plugins: [prodA, prodB...]`），独立路由前缀（`/docs/product-a/...`），独立 sidebar 与版本集，构建互不干扰、可增量缓存。
2. **单一信源**：Markdown 是唯一内容格式；Web 页面、PDF、（未来）帮助系统均由同一信源派生，杜绝多处维护。
3. **Web 与 PDF 同管线**：PDF 消费 Docusaurus 构建产物（含 admonition、代码高亮的最终 HTML），保证"所见即所得"。

## 4. 多产品 × 多版本 × 多语言模型

### 4.1 三维矩阵的管理策略

- **产品维度（Products）**：每产品一个 docs 多实例，独立团队目录 + CODEOWNERS。
- **版本维度（Versions）**：使用 Docusaurus 原生版本快照。
  - 开发中文档位于 `docs/`（标记为 next 或最新版）；
  - 产品发版时执行 `npx docusaurus docs:version:tag 2.3`，冻结到 `versioned_docs/version-2.3/`；
  - 已冻结版本原则上只接受缺陷修订（MR 走 backport 流程），不做功能重写；
  - 版本保留策略建议：每产品保留最近 3 个主版本文档，过期版本归档至 Git tag（可随时重建）。
- **语言维度（i18n）**：Docusaurus locale 目录结构 `i18n/<locale>/docusaurus-plugin-content-docs-*`。
  - 默认开发语言建议 **zh-Hans**，翻译派生 zh-Hant / en；
  - 内置翻译覆盖率检查：CI 中校验各 locale 文件与源文件的 diff 清单，缺失项在文档站显示"暂未翻译"徽标并回退默认语言，阻塞规则可配置（对外交付版本要求 en/zh-Hant 100%）。

### 4.2 版本发布与翻译协同流程

```
功能文档编写(zh-Hans, docs/)
   → 产品发版 MR
   → CI 翻译覆盖率门禁（en / zh-Hant 缺口列表自动生成）
   → 翻译团队认领（GitLab Issue 自动创建 / Crowdin 同步）
   → 翻译完成合入 i18n/
   → 版本冻结快照 (docs:version:tag)
   → 触发 PDF 全量构建（产品 × 版本 × 语言）
```

> 可选增强：接入 Crowdin / Weblate 做 TMS（翻译管理系统），提供翻译记忆与术语库，三语言规模化后收益显著。

## 5. 文档组织结构与 PDF 聚合（需求 7、9、10）

### 5.1 组织结构

- 产品的章节结构由 `sidebars.ts` 声明：章节（category）→ 页面（doc）→ 锚点，支持嵌套与跨目录引用。
- 一份 PDF 手册 = sidebar 中的一条"发布清单"（可用 category 顶层的 order 定义），**同一 PDF 由多个 md 文档按 sidebar 顺序聚合而成**，例如《AAS 安装部署手册》= 概述.md + 环境要求.md + 安装步骤.md + 初始化配置.md + FAQ.md。

### 5.2 PDF 生成管线（自动目录 + 页码）

```
Docusaurus HTML 产物
  → PDF 爬取器（按 sidebar 顺序抓取各页面 HTML，合并为单文档流）
  → 插入封面模板（HTML/CSS，按产品/版本/语言参数化）
  → 插入自动目录页（CSS target-counter 从章节标题收集页码）
  → Paged.js 分页引擎（@page 规则：页眉页脚、页码、章节分页、页边距）
  → Puppeteer 无头 Chromium 输出 PDF/A 标准文件
  → 制品库归档 + 门户下载页自动更新
```

关键能力实现：

| 能力 | 实现方式 |
|------|---------|
| 自动目录带页码 | TOC 条目 `<a href="#sec-id">` + CSS `a::after { content: target-counter(attr(href), page) }`，Paged.js 分页后自动回填真实页码 |
| 页眉页脚 | `@page { @top-center: string(章节名); @bottom-right: counter(page) }`，奇偶页可差异化 |
| 章节自动起新页 | `.chapter { break-before: page }` |
| 封面参数化 | 封面模板 = Handlebars HTML 模板 + `cover.yaml`（产品名、版本、日期、Logo、密级水印），内置 1 套企业标准封面，各产品线可在 `pdf/` 目录覆盖自定义模板 |
| 代码高亮 | 直接继承 Web 端 Shiki 渲染结果（含行号、语言标签） |
| Admonition | 继承 Web 端 note/tip/warning/danger/info 样式，打印友好配色 |

写作侧语法示例：

````markdown
---
title: 集群部署
---

:::note 提示
单机模式仅用于测试环境。
:::

:::warning 警告
升级前必须完成配置文件备份，否则可能导致数据丢失。
:::

```java
// 语言代码高亮（Shiki，支持 200+ 语言）
AppServer aas = AppServerFactory.create("aas-v11");
```
````

### 5.3 PDF 输出矩阵与触发策略

- **矩阵规模**：20 产品 × 平均 3 版本 × 3 语言 ≈ 180 份 PDF 手册族（每族含部署/开发/运维等多本手册）。
- **触发策略**：
  1. 产品发版 MR 合并 → 自动构建该产品当前发布版本 × 3 语言全量 PDF；
  2. 已冻结版本的修订合入 → 仅构建受影响手册（基于 md 文件 → 手册映射的增量计算）；
  3. 手动触发：门户后台支持任意 产品×版本×语言 组合即时出 PDF（按需构建，配合构建缓存约 2–5 分钟/份）。
- **产物管理**：PDF 归档至制品库（Nexus/Artifactory 或对象存储），命名规范 `{product}/{version}/{lang}/{manual}-{semver}-{date}.pdf`，门户下载页由 CI 自动更新索引。

## 6. 版本化与协作体系（需求 5、6）

### 6.1 Git 工作流

| 事项 | 约定 |
|------|------|
| 分支模型 | `main`（受保护，发布信源）+ `feature/doc-xxx` 短分支 + 版本修复 `hotfix/2.3-xxx` |
| 变更入口 | 一律 MR/PR，禁用直推 |
| 评审规则 | CODEOWNERS 按产品目录划权：改动 `products/product-a/**` 自动指派 A 产品线文档负责人审 |
| 门禁 CI | Markdownlint（格式）+ 链接检查（死链/锚点）+ Vale（术语与文风）+ 翻译覆盖率检查 |
| 预览 | 每 MR 自动构建 preview 站点（Netlify/Vercel 自建或 GitLab Pages 环境部署），评审者点链接看渲染效果 |
| 溯源 | 页面底部"在 GitLab 编辑此页" + 最近提交记录，读者可直接溯源 |

### 6.2 多团队权限模型

```
文档平台组（平台工程）      —— 仓库结构、CI/CD、PDF 管线、门户框架、封面模板库
   │
   ├─ 产品线 A 文档组 —— products/aas/**         （CODEOWNERS 写审权）
   ├─ 产品线 B 文档组 —— products/amdc/**、alb/**、ajdk/**
   ├─ 本地化组        —— i18n/zh-Hant/**、i18n/en/** 全局
   └─ 交付/售前团队    —— 制品库 PDF 下载权限（只读）
```

- 源码级权限：GitLab protected branch + group membership，产品线之间目录隔离；
- 非工程师贡献者：提供 GitLab Web IDE / VS Code Web 在线编辑路径，降低 md 提交门槛；
- 补充授权：可对接公司 LDAP/SSO 单点登录，评审消息推送企业 IM。

## 7. 门户站点与用户体验

- **统一门户**：站点首页为产品目录，按 4 个产品线分组导航，全局搜索（推荐 `docusaurus-search-local`，离线索引、内网可用）覆盖所有产品/版本/语言。
- **版本切换器 / 语言切换器**：Docusaurus 原生 Navbar 组件，读者在任一页面可切换版本与语言，URL 结构 `/docs/{product}/{version}/{lang}/{path}`。
- **渲染直出**：SSG 产物为纯静态 HTML，访问即渲染，无需服务端；内网部署仅需 Nginx/CDN。
- **部署**：主站 + 各 MR preview 均部署到公司内网静态托管（Nginx / MinIO + CDN / Kubernetes Ingress），支持灰度。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 20+ 产品全站构建慢 | 多实例增量构建 + CI 缓存（node_modules / .docusaurus / build）；按产品变更触发局部构建 |
| 三语言翻译滞后 | 翻译覆盖率门禁 + 回退显示机制 + Crowdin 流水线；交付版 PDF 仅使用 100% 翻译完成的 locale |
| 中文 PDF 字体一致性 | 统一打包思源黑体/宋体（SIL 开源许可）到构建镜像，PDF 管线锁定字体版本 |
| 历史文档格式迁移成本 | 提供转换脚本（Pandoc）+ 文档平台组驻场支持，按产品线分批 |
| 已冻结版本的误改 | versioned_docs 目录 CODEOWNERS 升级为双人评审 + CI 拦截非 fix 类提交 |

## 10. 交付物清单

1. `docs-repo` 文档源仓库（含脚手架、CODEOWNERS、CI 模板）；
2. 文档中心门户站点（内网部署 + MR preview）；
3. PDF 自动化构建流水线（含默认企业标准封面模板 + 各产品自定义机制）；
4. 运维手册：平台组运营文档、写作规范（Markdown/Admonition/术语表）、翻译协作指引。
